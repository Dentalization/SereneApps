# Smartphone dental 3D reconstruction: research walkthrough

**Status: 2026-09-25.** This is a walkthrough of the current implementation, the first live-capture diagnosis, and relevant research. It is not a completed reconstruction experiment. No code or scan was changed or rerun for this research note.

> **IMPLEMENTED ≠ EXPERIMENTALLY VALIDATED ≠ CLINICALLY VALIDATED**
>
> Smartphone/reference/repeated-capture validation: `DATASET_UNAVAILABLE`.

## 1. The goal

The user wants a camera capture that produces recognizable geometry for every visible tooth. A useful demonstration must show which tooth surfaces were observed in multiple real views, which surfaces remain unseen, and whether the geometry agrees with an independent reference. A plausible complete arch generated by a learned prior is not equivalent to a measured scan. A good novel-view render is not, by itself, evidence of an accurate STL.

## 2. What already works

The mobile Dentist Scan 3D flow can capture and upload a video. The backend inspects the media, records its identity, runs measured frame acquisition, queues a reconstruction attempt, and keeps attempt provenance. The Python OpenCV engine extracts and matches image features, estimates camera geometry, triangulates sparse points, and exports OBJ/PLY/STL plus preview. X-Core can display a diagnostic result while marking it unsuitable as a ready, measured dental mesh. Research schemas and validation infrastructure exist for future real videos, repeat captures, and reference surfaces.

See [the exact execution path](BASELINE_INTEGRITY_AUDIT.md) for the mobile → Node → Python → X-Core handoff. That historical audit describes the engine as two-view/version 2.1. The current implementation has additional-view registration/version 2.2, but **the mesh still comes from the best frame pair**; additional registered poses have not become dense multi-view surface evidence.

## 3. What the first live capture showed

The first 15.3-second, 1080 × 1920 portrait video decoded correctly and yielded 18 selected frames. The chosen pair (frames 357 and 457) produced 86 points and 94 triangles. Reprojecting every point onto the selected image located all 86 below the mouth—on chin, clothing, or background—and none in the visible tooth area. The mouth also changed between the two images. A subsequent check registered seven camera views, yet the displayed mesh remained the same non-dental, 86-point surface. [The capture audit](FIRST_CAPTURE_GEOMETRY_AUDIT.md) records these observations.

This establishes two different blockers in sequence:

1. **Input and target identity:** the recorded image evidence did not support tooth geometry. Global blur/exposure and match counts can pass while matches belong to skin or clothing.
2. **Reconstruction architecture:** camera registration alone does not make a dense tooth surface. The current best-pair, image-plane Delaunay mesh is sparse diagnostic geometry, not multi-view stereo.

Neither more triangles nor a tooth-shaped fallback can repair missing observations. The diagnostic mesh remains useful to inspect failures, provided the UI retains its experimental/invalid-scale status and disables clinical measurement claims.

## 4. The evidence-based path forward

| Stage | Required evidence and decision | Current gap |
| --- | --- | --- |
| Capture protocol | Each target tooth surface is sharp, sufficiently large, and visible from overlapping views with camera translation; lighting and mouth configuration stay stable. | One unsuccessful capture; no demonstrated per-tooth coverage. |
| Camera model | Fixed lens/zoom plus calibrated intrinsics and distortion for the capture configuration; independent physical scale if measurements are required. | Intrinsics can be estimated from frame dimensions; scale is unvalidated. |
| Dental region | Tooth masks or reviewed regions of interest remove lip, chin, clothing, background and unstable specular evidence from geometry. | No validated dental-region gate for the current reconstruction. |
| Keyframes and matches | Select useful overlap/parallax and new tooth coverage; geometrically verify multi-frame tracks on teeth. | Uniform frame sampling and global image checks do not establish these properties. |
| Sparse SfM | Register views, triangulate new dental points across many pairs, optimize poses/points jointly, and report residuals, track lengths, connectivity, and parallax. | Extra poses can register, but surface points still come from one pair. |
| Dense reconstruction | Recover consistent depth from several observed views; fuse supported depth into a dense dental point cloud. | No executed dense multi-view stereo path. |
| Mesh and coverage | Remove outliers and unsupported faces; label visible versus unobserved areas, with coverage evidence for each tooth. | Vertex/face counts alone can certify the wrong object. |
| Validation | Compare repeated real captures with an independently acquired, scale-calibrated reference STL/PLY using a prespecified alignment and per-tooth metrics. | `DATASET_UNAVAILABLE`; no trueness, precision, or clinical result can be reported. |

COLMAP's [original project tutorial](https://github.com/colmap/colmap/blob/main/doc/tutorial.rst) separates sparse structure-from-motion from dense multi-view stereo and recommends texture, overlap, stable lighting, and actual viewpoint translation. Its [camera-model guidance](https://colmap.github.io/cameras.html) explains why lens parameters and distortion need to be handled explicitly. [OpenMVS](https://github.com/cdcseacave/openMVS/blob/develop/docs/wiki/Usage.md) is a candidate dense stage after SfM, not proof that dental input will succeed.

## 5. Paper walkthrough: what each result actually establishes

| Primary paper | Study and finding | What it does **not** establish for this project |
| --- | --- | --- |
| [Yang et al., *Cost-Effective Full-Color 3D Dental Imaging Based on Close-Range Photogrammetry* (2023)](https://pmc.ncbi.nlm.nih.gov/articles/PMC10669235/) | Close-range photogrammetry using a small dedicated intraoral camera. On dental models, 57.7 ± 3.2% of reconstructed points fell within ±0.1 mm and 82.4 ± 2.7% within ±0.2 mm of reference. They also showed visually distinct anterior teeth in vivo. | It did not use an ordinary phone held outside the mouth. The in-vivo volunteer had no quantitative reference mesh; authors distinguish this imaging use from high-precision orthodontic/surgical scanning. |
| [Xu et al., *TeethDreamer* (MICCAI 2024)](https://arxiv.org/abs/2407.11419) | Five intraoral photos, tooth segmentation, generated multi-view color/normal images, then neural surface reconstruction. Trained on 3,200 photo/scan cases and evaluated mesh distances against reference models. [Code](https://github.com/ShanghaiTech-IMPACT/TeethDreamer) is available. | Generated viewpoints and surfaces may represent learned plausible anatomy rather than observed anatomy. The released workflow reports an A100 40 GB test setup; paper reports roughly 10–20 minutes per reconstruction. |
| [Chen et al., *Automatic 3D Teeth Reconstruction From Five Intra-Oral Photos Using Parametric Teeth Model* (2024)](https://pubmed.ncbi.nlm.nih.gov/37204961/) | Fits a statistical tooth model to predicted contours from five images; five-fold evaluation on 95 orthodontic cases. | A good parametric fit is not direct measurement of all patient-specific crown surfaces. Its stated use is remote-consultation visualization. |
| [Miao et al., *Dental3R* (2025 preprint)](https://arxiv.org/abs/2511.14315) | Geometry-aware image pairing, DUSt3R initialization, and Gaussian Splatting; 195 video cases plus a large sparse-photo cohort. This is directly relevant to pair selection under difficult intraoral views. | Main quantitative metrics are PSNR/SSIM/LPIPS for rendered views, not per-tooth STL error versus reference. The paper's sparse-photo case count is inconsistent in its own text (950 versus 956), so dataset accounting needs clarification before reproduction. Its reported workstation has an RTX 4090. |
| [Zheng et al., *Teeth Reconstruction and Performance Capture Using a Phone Camera* (ICCV 2025)](https://openaccess.thecvf.com/content/ICCV2025/html/Zheng_Teeth_Reconstruction_and_Performance_Capture_Using_a_Phone_Camera_ICCV_2025_paper.html) | Uses semantic tooth segmentation and shape/face priors to recover teeth visible during facial-expression capture; experiments include four people filmed on a phone. | Face-avatar reconstruction is not a full intraoral scan or validation of every dental surface. Priors must be labeled as inferred geometry. |
| [Li et al., smartphone video and deep learning for full-arch implant scan (2025)](https://pubmed.ncbi.nlm.nih.gov/40055947/) | Ten repeated scans of an edentulous six-implant model with scan bodies and desktop-scanner reference. The better trained variant improved trueness, but the authors state accuracy was not sufficient for clinical use. | Scan-body/implant position transfer is not natural-tooth surface reconstruction. Its numerical accuracy cannot be imported into SereneApps. |
| [Smartphone position study on complete-arch dental models (2024)](https://pubmed.ncbi.nlm.nih.gov/39077296/) | Repeated in-vitro scans tested different phone angles against a laboratory reference and found angle-dependent surface differences. | Open stone casts do not reproduce saliva, lips, tongue, movement, or posterior access in vivo. |
| [Gianfreda et al., smartphone photogrammetry for implant position transfer (2026)](https://pubmed.ncbi.nlm.nih.gov/42031357/) | Twenty repeats on an edentulous implant model against an industrial scanner; measured implant position and angulation. | The study intentionally minimizes mesh-tessellation effects. Its implant-position figures are not tooth-surface accuracy figures. |

### How to interpret the papers

- **Measured photogrammetry/MVS** should be the first reproducible geometry baseline: every surface claim needs support from actual image observations.
- **Dental shape priors and generative methods** are research comparators for incomplete views. Their output must identify inferred regions and be evaluated against held-out reference surfaces.
- **Novel-view synthesis scores** assess image appearance. They cannot replace surface-distance, completeness, and repeatability measurements.
- **Implant scan-body studies** answer a different measurement question from the user's goal of reconstructing every natural tooth.

## 6. A reproducible evaluation plan, once real assets exist

1. Acquire authorized, unmodified phone videos with device/lens metadata and several independent repeats per object. Record the exact capture path and unsuccessful attempts too.
2. Obtain an independent reference surface for the same dental anatomy, with scanner provenance, units, coordinate system, and acquisition timing. Predefine per-tooth regions and exclusions.
3. Freeze reconstruction engine/version, model weights, parameters, input hashes, frame selection, calibration and all intermediate artifacts before comparing results.
4. Align rigidly under a prespecified procedure. Determine scale independently; do not fit scale to minimize reference error. Evaluate held-out anatomical surfaces, coverage, signed/absolute deviation distributions, and repeatability per tooth and per surface.
5. Report failure rate, missing teeth/surfaces, processing time, and uncertainty alongside any error metric. Keep model/phantom and in-vivo cohorts separate. Do not promote a diagnostic mesh to a clinically validated result based on visual appeal.

The existing [research runbook](README.md), [dataset schema](smartphone-dataset.schema.json), and [validation input schema](validation-input.schema.json) are infrastructure for this work, not substitute data. Current dataset-dependent outputs must remain `DATASET_UNAVAILABLE`.

## 7. Decisions still open

The immediate research decision is whether the phone's current camera position can reliably show the posterior, lingual, and interproximal surfaces needed for the intended product claim. That should be established through reviewed capture frames before engine comparisons. If those surfaces are not visible, the honest scope may be visible-surface documentation rather than complete-arch metrology, or the capture hardware/protocol may need to change.

The next engineering benchmark should compare (a) a classical sparse-SfM plus dense-MVS baseline and (b) a dental-prior approach on the **same real, referenced captures**. The benchmark has not been run. No paper result above is a SereneApps validation result.
